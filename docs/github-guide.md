# 민수용 GitHub Desktop 가이드

이 저장소에서 작업할 때 헷갈리면 이 문서만 보면 된다.
규칙은 딱 하나만 기억해도 된다: **main에서 직접 작업하지 않는다.**

## 1. 앉으면 하는 루틴 (매번, 순서대로)

1. **Fetch origin** — 오른쪽 위 버튼. 서버의 최신 상태를 확인만 한다
2. **Current Branch가 `main`인지 확인** — 위쪽 가운데 표시
3. **Pull origin** — Fetch 후 "Pull origin"으로 바뀌면 눌러서 최신을 받는다
4. **New Branch** — Branch 메뉴 → New Branch → 이슈에 적힌 브랜치명 입력
   (예: `feature/ble-beacon`)

이 4단계를 마친 뒤에야 코드를 만진다. 어제 쓰던 브랜치를 이어서 할 때도
1~2번(Fetch, 브랜치 확인)은 꼭 한다.

## 2. 커밋 단위

- **컴파일이 되는 상태 + 한 가지 변화**가 1커밋이다.
  "광고 데이터에 상태 필드 추가"처럼 한 문장으로 설명되면 적당한 크기다
- 메시지 형식: `영역: 한 줄 요약`
  - 예: `node: BLE 광고에 시설 종류 추가`
  - 예: `handset: RSSI 이동평균 창 8로 조정`
- 하루 종일 커밋 0개면 덩어리가 너무 크다는 신호다

## 3. Push → PR 만들기

1. 커밋을 쌓았으면 **Push origin** (처음이면 "Publish branch")
2. Desktop에 뜨는 **"Create Pull Request"** 버튼 → 브라우저가 열린다
3. 제목은 이슈 제목과 비슷하게, 본문에 `Closes #이슈번호` 한 줄과
   확인 방법(사진·영상 링크)을 쓴다
4. **Create pull request** 누르고 이령에게 알린다 → 리뷰 → 병합
5. 병합되면 루틴 1번부터 다시 (main으로 돌아가 Pull, 새 브랜치)

## 4. 사고 수습 3종

| 상황 | 해결 |
|---|---|
| 커밋 **전**인데 수정을 되돌리고 싶다 | 왼쪽 파일 목록에서 우클릭 → **Discard Changes** (그 파일의 수정이 사라진다 — 되돌릴 수 없으니 파일명 확인) |
| 커밋 **직후** 실수를 알았다 (Push 전) | 왼쪽 아래 **Undo** 버튼 — 커밋이 풀리고 수정 내용은 남는다. 고쳐서 다시 커밋 |
| **Push까지 한** 커밋을 되돌리고 싶다 | History 탭에서 해당 커밋 우클릭 → **Revert Changes in Commit** — 되돌리는 새 커밋이 생긴다. 옛 커밋을 지우려 하지 말 것 |

셋 다 애매하면 아무것도 누르지 말고 이령에게 화면을 보여 준다.

## 5. 충돌(conflict)이 났을 때

Pull이나 병합 때 "conflicts" 경고가 뜨면:

1. 당황하지 않는다 — 같은 줄을 두 사람이 고쳤다는 뜻일 뿐이다
2. Desktop이 알려 주는 충돌 파일을 에디터로 연다
3. `<<<<<<<`, `=======`, `>>>>>>>` 마커 사이에 두 버전이 보인다.
   남길 내용만 남기고 **마커 세 줄은 전부 지운다**
4. 파일을 저장하면 Desktop의 충돌 표시가 체크로 바뀐다 → 커밋으로 마무리
5. 어느 쪽을 남길지 판단이 안 서면 그 상태로 이령에게 물어본다

## 6. 금지 4항

1. **브랜치 확인 없이 작업 시작 금지** — 코드를 만지기 전에 Current
   Branch부터 본다. main이면 새 브랜치를 만든다
2. **100 MB 넘는 파일 커밋 금지** — GitHub가 거부한다. 영상·대용량 CSV는
   커밋하지 말고 링크로 공유 (`data/raw/`는 .gitignore에 이미 제외돼 있다)
3. **한글 파일명 지양** — 도구에 따라 깨진다. 파일명은 영문 소문자와
   하이픈으로 (문서 내용은 당연히 한국어)
4. **main에 직접 push 금지** — 저장소 보호 규칙으로 막혀 있지만,
   시도 자체를 하지 않는 습관을 들인다
